## Shared integration operation

When native evidence supports the stated lifecycle:

1. Read the current page, manifest and private bindings immediately before editing.
   Reuse the existing Start Here/task navigation; do not add a duplicate Teams
   tab, channel post or alternate assistant runtime.
2. Link the exact supported native agent entry and maintained operator guide.
   Label a maker-only or fictional pilot accurately. Do not present a conditional
   runtime as available to ordinary users or promote it to real policy use.
3. Add or amend only the assistant's owned capability/artefact records and managed
   page content. Preserve unrelated controls, capability modes, quiet status,
   source/identity contracts, schedules and existing evidence history.
4. Read back the exact native entry, guide bytes and managed page/manifest state;
   reopen the entry, check citation links, and repeat without duplicate artefacts
   or additional page versions. Preserve failed/partial results rather than
   advancing acceptance from local tests.
5. Update CE-05, the queue/handoff and registry only to the evidenced lifecycle.
   Native runtime, source review, operator access and production promotion remain
   distinct. Keep unfinished requirements open.

If exact eligibility or required behavior is unavailable, retain the precise
operation/result and supported fallback while leaving native acceptance open.
Do not replace the requested native assistant with the Codex prototype, assign a
licence, start a trial, grant access, create consent or enable tenant features.

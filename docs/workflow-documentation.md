## Version control and maintenance

- The latest release register, currently `docs/workflows/v1.7.0/register.json`, is the maintained structured source. Each
  entry names its trigger, inputs, ordered work, output, owner lane, failure/retry
  rule, execution mode, evidence status and instructions. Diagram sources are
  readable Mermaid; matching PNGs are static reading aids generated by installed
  Graphviz from the same steps. These diagrams document business/technical stages,
  not an export of every individual Power Automate action.
- `scripts/ppg_workflow_docs.py --release VERSION --render` builds a new guide and diagrams; `--release VERSION --check`
  validates coverage and the release's frozen documentation checksums. The release
  manifest hashes register, diagrams, guide and referenced instructions. It does
  not hash or certify the current deployed definitions. Git commits retain edits
  and review; an update to a published baseline needs a new documentation release
  rather than silently overwriting the hosted release files.
- Documentation release, SharePoint page/file version, native flow revision,
  policy edition and human approval are distinct. `deployedDefinitionSHA256: null`
  means unverified, not absent. Do not fill it from a builder or successful run.
  The native owner must record exact environment/component identity, retrieved
  definition hash, connection references/state, readback time and deployment
  receipt privately before claiming a deployed revision matches a release.
- A workflow change updates the register, diagram, operating instructions,
  recovery route and evidence label together. Preserve previous native page/file
  revisions and immutable release files. Migrate the hub link only after readback
  verifies the new guide and its actual links/images; retain a prior link preimage.
  Reverting a guide link does not roll back workflows, records or approvals.
- The preferred SharePoint structured Word route was evaluated first using the
  existing exact-account eligibility evidence. Production maker/connector
  entitlement remains unqualified. The supported fallback is a native SharePoint
  reading page plus versioned source/downloads in the existing library. No new
  licence, connector, document runtime, permissions or settings is required.

Ordinary-user access, live workflow state, source freshness and full solution/ALM

## Reading copies and the text-only repository

The publication gate rejects binary files. Keep generated PNG reading aids in
SharePoint and ignored locally; Git versions the editable Mermaid sources and
expected PNG hashes. The native guide displays all diagrams without a local
renderer. For a fresh checkout, run
`.venv/bin/python scripts/ppg_workflow_docs.py --render-images` to materialise
missing reading copies against their frozen hashes. If renderer bytes differ,
retain the native download rather than changing the old release's hashes.
`--check` reports unmaterialised reading aids separately; missing/changed frozen
text remains an error. A live linked instruction changing after release is
reported as reference drift, without rewriting that release's snapshot.

For an update, prepare a new numeric version directory/register, revise the
release/as-of and row versions/diagram paths, and build it with
`--release VERSION --render`. Existing release manifests cannot be overwritten.

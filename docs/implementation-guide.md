# Fast, consistent implementation

## Select work without restarting discovery

Use the existing [execution queue](../conductor/execution-queue.md) and
[value-first slices](maturity-capability-plan-20261018.md#value-first-sequence--user-refinement-18-october-2026).
Choose an authorised slice with available inputs and a free native owner. A track
marked ready may contain an external-media or actor-access hold: inspect its exact
next action. Continue independent preparation or a lower-cost usable fallback.
Do not add another track, parallel writer or framework just to record a blocker.

Routine local preparation, reversible scoped implementation and verification are
already authorised within the selected work. Ask only for a genuinely missing
material decision, user-only authentication or scope-changing effect. Existing
recipient/clinical-authority/access boundaries still apply. Never treat elapsed
waiting as consent. Use the already recorded user preferences, not another setup
interview. This guide creates no extra approval ceremony.

## Standard delivery and completion

Use `.venv/bin/python` and affected offline tests; use CLI for native metadata,
configuration and readback where supported. Native UI remains appropriate for Word
rendering/editability, form usability and user-role evidence. For a write retain
before-state, identity/version, minimal delta, readback and recovery evidence.
Reuse existing guards rather than introduce a new transport/helper in every task.

A slice is done when its promised output is usable, its proportionate checks pass
and its actual operating mode is recorded. A fictional native proof is not production
adoption. A documented fallback can complete a useful slice; label an unavailable
optional feature deferred. Update only the selected plan/metadata and concise
handoff; do not rerun all 900+ setup checks or broad tests after every native read.

Use short, scoped commits. Stage explicit files so another writer's changes remain
untouched. Worktrees may isolate local edits when needed, but never isolate native
ownership or shared authentication. Before publication follow ALM-01; a commit
or successful Gitleaks scan alone is not permission to publish operational material.

## Latest useful features, not automatic adoption

Recheck official feature prerequisites when selecting a feature; do not mistake a
new release, installed plugin or Developer entitlement for production availability.
Prefer existing Lists forms/views, standard SharePoint automation and Word
coauthoring. SharePoint structured generation remains the preferred structured
output route, with currently unqualified maker/production eligibility. Its current
conditional-section/web-edit and form-versus-flow visibility limitations remain
part of output qualification. [Microsoft guidance](https://learn.microsoft.com/en-us/sharepoint/copilot-in-sharepoint-structured-document-generation)

Stable Python 3.15.0 is now installed privately and selected for local work. The
pinned Open XML 3.5.1 matches the current NuGet package. Other shared runtime/CLI
upgrades need affected-operation compatibility, rather than wholesale refresh.
ALM-02 stays open for .NET and remaining runtime coverage. No new dependency or
feature should be introduced without removing a concrete task or defect.

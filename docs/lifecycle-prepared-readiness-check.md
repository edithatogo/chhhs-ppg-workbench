# Prepared-revision readiness observation

> Current workflow baseline: [versioned register and status reconciliation](workflow-documentation.md). Dated qualification sections below retain their original scope; read the current baseline before treating an earlier limitation as current.

The optional `Check readiness` case-work mode has passed the missing-finding hold
and consistency checking of one explicitly fictional version-bound finding.
Neither result is a real content assessment or permission to progress. It uses the existing manual case-reference entry, ownership checks
and same-execution prepared reader. It creates no native object, column, finding,
assignment, decision, notification or case change.

The [readiness helper](../tools/lifecycle/build_prepared_readiness_check.py) reads
the complete existing consultation and readiness collections with the qualified
same-site SharePoint connection. Consultation coverage is recalculated for the
current prepared scope and an explicit fictional required-role plan; a saved
coverage receipt cannot substitute. The original source is never a prepared draft.

Readiness scope matches all four fields: CaseUID, document reference, exact reviewed
version reference and SHA-256. Exactly one scoped finding must exist. It must be a
fictional Ready for decision assertion with a unique native/event identity, retained
ETag, assessor, date, rationale, evidence and None recorded or Resolved conditions.
Future dates, missing evidence, Not assessed, Needs changes and Not applicable do
not pass. Duplicate identities or superseding references anywhere in the complete
history hold. Multiple scoped findings and correction chains require later explicit
resolution; the helper does not silently select a newest record.

Both complete histories use minimal metadata to retain per-row opaque ETags and
are read again. Comparisons retain every field except the
request-generated `odata.id` response identifier, normalized to null with the
previously qualified `union` expression, including actual Id/GUID, opaque
ETags, dates and business fields. Any continuation link or observed change holds.
Fresh case, draft, qualification receipt, template, source and baseline metadata
must still match the same-execution prepared reader. A failure returns an explicit
held observation; every branch remains read-only.

The result separates recorded-finding consistency, consultation coverage and native
context revalidation. `readinessEvidenceConsistent` requires all three; an empty
List cannot pass. Content readiness, actor authority, policy approval and progression
are always false. This is a snapshot of technical consistency, not substantive
assessment or permission for a later action. Any later write needs fresh validation.
The existing readiness List form remains the human recording route.

Five focused local checks cover GET-only/resource boundaries, unsafe or truncated
history requests, nonempty fictional role plans, action composition, full-history
supersession/identity checks and concurrency-token preservation. The assembled
candidate preserves existing context/projection/preparation action graphs, adding
only explicit mode admission and reuse of preparation for readiness. The reviewed definition was saved to the existing flow with its existing connection.
Actual first-party manual entry recomputed complete consultation coverage on the
edited draft, revalidated native context, found zero scoped readiness findings and
returned an explicit hold. All six existing projection writers skipped. Both reads
of each complete collection retained native row ETags, IDs and GUIDs. Independent
before/after case, histories and four artifact metadata snapshots were unchanged
apart from request-generated transport IDs. The exact current definition and
connection references were verified stopped; the previous working definition is
retained as rollback. No readiness finding or assessment was recorded.

A separately owned native List form subsequently retained one clearly fictional
finding on the exact edited draft. Actual Check readiness and an identical actual
form repeat both selected that unique finding, verified its native identity/token,
DateOnly value, exact prepared scope, consultation coverage and fresh context, and
returned technical evidence consistency with zero writes. Meaningful receipts
matched apart from run/observation time. Independent case, both histories and four
artifact snapshots were unchanged, including the finding and all original records.
The flow was verified stopped with the exact unchanged definition and references.
The earlier missing-finding proof is preserved.

These prove fictional positive consistency, repeat and missing-finding behavior;
adverse recorded findings and ordinary-user access remain unqualified. Real
assessment, actor authority, readiness grants and approval remain false. Private

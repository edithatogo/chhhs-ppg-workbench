# Policy-management maturity and capability plan — 18 October 2026

## Direction and evidence

The user does not control the upstream register. It remains an external, read-only
source dependency: no replacement, writeback, schema change, central workflow
redesign or upstream-owner action is a prerequisite for local benefit. Preserve
source facts separately from local priorities, accepted roles, dates and decisions.
A local completion does not update the central register. Display discrepancies and
prepare an optional handoff for its existing custodian; do not send it automatically.
A missing source row is not withdrawal. Source delay must not prevent work against
an explicitly identified last accepted snapshot, subject to existing stale-input guards.

## Commissioned work and sequence

The priority refinement below supersedes track-wide ordering: low-effort local
value must not wait for full lifecycle completion. Preserve the active lifecycle
writer and existing in-flight operations. The following maps execution homes:

1. Existing LC-02–05 tasks cover:
   ordinary-user entry, complete fictional cycle, adverse branches, publication
   evidence, closure and next occurrence. Where publication is external, record
   authenticated publication evidence and handoff status without controlling QHEPS.
2. New [review follow-up track](../conductor/archive/ppg_review_followup_20261018/index.md)
   makes ownership, waiting, priority and next action usable; notifications remain
   preview-only pending explicit recipient/action instruction.
3. New [adoption and measures track](../conductor/archive/ppg_operational_adoption_20261018/index.md)
   establishes ordinary-user proof and measured benefit. Initial observation can
   proceed on already delivered routes; full-cycle acceptance waits for lifecycle.
4. New [document-control continuity track](../conductor/tracks/ppg_records_continuity_20261018/index.md)
   improves edition discovery and recovery within the existing local workspace.
   Original-media recovery remains with the existing archive owners.

One automation increment and one workflow/template increment at most. These new
tracks are queued; planning creates no new native writer. Preparatory reads are
eligible when a lane is free. Existing owners select and re-read exact target state
before any change. No new chats, schedules or framework are required.

## Value-first sequence — user refinement, 18 October 2026

Select small deliverables, not whole tracks, in this order. Value and effort are
qualitative planning estimates, not measured savings or delivery promises.
Low = existing fields/views/docs with no new service; medium = a bounded schema,
flow or recovery change; high = multi-stage integration or new runtime eligibility.
Do not interrupt an active native transaction to reprioritise.

| Rank | Task slice | Value / effort | Useful output and blocker treatment |
|---|---|---|---|
| 1 | RF-01 + RF-03a | High / low | Reuse existing fields for an actionable local queue: missing next action, waiting reason, unaccepted ownership and agreed-date exceptions. Read fields/effects, then improve views/labels. No schema, new app or reminder delivery prerequisite. |
| 2 | RC-01 + RC-02a | High / low | Clear draft/reference/externally confirmed issued links and visible uncertainty. Reuse existing evidence; missing archive media or unconfirmed authority must not block navigation improvements. |
| 3 | OA-01 + OA-03 | High / low | A short reusable task-observation sheet and baseline definitions; use existing CSV/List route. Real participant availability does not block preparing instrumentation. |
| 4 | RF-02 + RF-04 | High / medium | Fill only demonstrated local data gaps and provide a follow-up preview. No send, new approval system or complete lifecycle dependency. |
| 5 | RC-04 + RC-05 | High / medium | Bounded copied-fixture recovery and maintainable restart guide, reusing current receipts rather than another recovery engine. |
| 6 | OA-02 + OA-05 | High / medium | Ordinary-user evidence for already delivered tasks when a participant is available; final full-cycle result consumes lifecycle proof later. Missing participant holds only that observation. |
| 7 | OA-04 | Medium / medium | Power BI only for a recurring question existing measures cannot answer. Start from reconciled export; workspace, refresh and audience gates hold only Power BI, not reporting. |
| 8 | RF-06 | Medium / medium | One relevant source-change candidate beyond the current pilot only when its repeated manual check is identified. No broad surveillance programme. |
| 9 | RF-05 / RF-03b / RC-03 | Conditional / medium–high | Planner, Approvals, custom form and records-admin capability checks only when simpler paths leave a specific gap. Do not spend time discovering all tenant capabilities first. |

Existing full lifecycle remains important but complex; its writer continues the
current bounded slice. Production Word/Copilot/Dataverse are conditional later
work, never prerequisites for ranks 1–6. RC-02b (external handoff state) and final
lifecycle reporting consume actual evidence when available; do not invent it.

Value adds included without another platform: single-action navigation from a
queue row, separate agreed local versus source due dates, a visible reason a case
is waiting, duplicate/change candidate suppression using existing identities,
plain-language freshness/unknown states and reusable handoff/recovery instructions.
Measure discovery time, missing follow-up information, corrections and preparation
effort before expanding. No numerical clinical risk score is introduced.

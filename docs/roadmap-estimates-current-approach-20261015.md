# Revised delivery estimates — 15 October 2026

These replace the earlier broad solo-developer day estimates for planning. They
are judgement ranges based on remaining tasks and reusable current components,
not measured productivity statistics, commitments or a blanket AI speed multiplier.

## Basis

- Existing Lists/library, qualified source-sync contracts, manual package tools,
  archive fields/views, authentication routes and task plans can be reused.
- The recent edition/currency increment demonstrated that additive native fields,
  views, a disposable history/replay check and documentation can fit one session.
  Commit intervals are not reliable active-time measurements: chats overlap and
  timestamps include waiting, so no throughput rate was calculated from them.
- Current working-tree delivery notes report metadata prefilling delivered with
  hosted-byte/output checks. Those ongoing files are another writer's changes;
  this estimate does not certify them or count them as remaining Autofill work.
- Time means one active agent-led engineering workstream, including ordinary tool
  execution, targeted tests, native save/run/readback and handoff. It is not the
  user's personal labour, a calendar finish date or only code-generation time.
- Lower ranges assume qualified access and reusable interfaces work. Upper ranges
  allow bounded repair/retest. Unknown product access, a new runtime, substantial
  redesign or additional security/cutover scope requires re-estimation.
- Policy assessment, actual identity/currency decisions, consultation responses,
  licences/admin enablement, ingestion queues and future scheduled observations
  are separate elapsed-time dependencies. They cannot be promised in these hours.
- Existing planned-track acceptance remains intact. Unselected candidates describe
  a small first usable increment, not a complete enterprise feature. Migration
  and adapters are deliberately unestimated until a concrete contract exists.

Impact is potential benefit to this workbench, **5 highest**, not measured savings.
P1 = next core work or prerequisite check; P2 = useful follow-on; P3 = conditional;
P4 = defer. Priorities are recommendations and do not reorder another active writer
or commission the deferred candidates.

Incremental assessor/version/findings/evidence recording and views; existing assembler checks reused. Not a standalone rebuilt workflow.

Confidence: Medium. Included in combined assurance/readiness estimate of 5–10 h; do not sum a separate full build.

### Evidence finder / archive navigation

Remaining four-task discovery checks, useful links/views and honest search fallback; new archive edition views already delivered.

Confidence: Medium-high. Large-scale enrichment/OCR/searchable derivative generation excluded.

Deterministic snapshot diff, established UID join, affected-case links, replay/unknown checks and one qualified output.

Confidence: Medium-low. Depends on supported snapshot acquisition and stable identity; no local decision writes.

### Consultation and ownership handoff

Confidence: Medium-low. Waiting for responses, assignments and substantive consultation excluded.

Confidence: Medium-low. Additional tuning/retests after failures can extend range; no independent operational benefit assumed.

### Suggested metadata with Autofill

One or two derived suggestion columns, sample extraction/correction and readback. Distinct from current deterministic manual prefilling.

Confidence: Low. Eligibility and processing charges unresolved; no spending implied. Existing manual prefilling reported delivered in current working tree.

### Unattended package generation

Reuse assembler contracts; native record selection, draft generation/assembly, hashes, output history, duplicate/retry and edit preservation. Evaluate preferred structured-document route first.

Confidence: Low. Current manual tools remain working. Requires a qualified generation path; not just adding a schedule/button.

### Broader authoritative-source surveillance

One authenticated source family, captures/provenance, deterministic changes, exceptions and review queue output with failure proof.

Confidence: Low. Protected-source access and currency qualification can dominate elapsed time; no broad intranet estimate.

### Federation / CareOps / Atlas adapters

Consumer contract and actual endpoint/access need definition before a credible implementation range.

Confidence: Low. No concrete consumer/contract established; do not manufacture precision.

### Dataverse migration / model-driven app

Prove a Lists limitation, inventory relationships/security, migration reconciliation and cutover/recovery before estimating build.

Confidence: Low. Not a simple AI speed-up of an unspecified migration. No migration need demonstrated.

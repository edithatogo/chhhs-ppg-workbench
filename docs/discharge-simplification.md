cloud-executed or automatically enforced process.

Use the exported pinned inventories, prior prepared snapshot and rows from exactly
one document/revision. Supply a JSON object mapping every guide-section ID to its
explicitly reviewed wording, then run:

```sh
.venv/bin/python scripts/ppg_review_simplification.py \
  --source SOURCE.json --template TEMPLATE.json --previous PREVIOUS.json \
  --rows ROWS.json --guide-texts GUIDE-TEXTS.json \
  --revision NEW-REVISION --guide-version NEW-GUIDE-VERSION \
  --rationale 'Reason for reconciling this edit' --output NEW-SUCCESSOR.json
```

The command requires new revision identities, preserves section evidence bindings,
refuses changed scope/definition metadata and creates a new output exclusively.
It never overwrites the exported row or performs native writes. Inspect the proposed
guide text before saving a successor with the existing create-only native route.
Hash matching proves version binding, not semantic or clinical correctness.

site access; native assignments include Read and Edit groups. This is configuration
evidence only. No ordinary-user identity was available for an independent runtime

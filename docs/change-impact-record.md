# Change and impact record

Use one versioned SharePoint record per document revision or no-change review. It accompanies the maintained document and its guide; it is not a second approval workflow. The native form works in the browser. Source metadata stays read-only.

1. Open **PPG Change and Impact**, choose New, and copy the existing DocumentUID and exact from/proposed edition. Assign one stable ChangeKey; search it before saving. Keep incomplete content in Draft.
2. Select all review triggers; separately assess magnitude and urgency. Scheduled review is a trigger, not a major change. Use Unassessed until an authorised reviewer applies current local definitions.
3. Record major and minor changes as bullets with section references, reasons and evidence. For no-change review select No change and explain the review scope/outcome. Unknown is not None.
4. Record each interaction as target UID/title, exact edition or legislative provision, relationship, affected section, evidence and unresolved applicability. Use existing relationship/requirement records; do not infer HHS applicability from departmental scope.
5. Record implementation actions, proposed responsible role, dependencies, guide edition and unresolved/deferred issues. Link de-identified incident/audit recommendations; do not include patient details.
6. Save, reopen and verify. Native version history preserves corrections. Do not replace an existing record on retry or rewrite a previously issued summary; create a successor for a later document revision.
7. When a human decision exists, link the actual decision evidence. RecordState does not grant authority. Populate approved edition/effective date only from that decision. Readers see major/minor changes; governance users can open the same record for rationale and dependencies.

Native required fields, choices and unique key protect ordinary capture. Cross-record edition consistency, decision authority and valid clinical content require review; a direct form is not a clinical validator. No notification or transition automation is installed.

## Output and recovery

Preferred SharePoint structured document generation was reconsidered against the retained qualification: exact output/edit/regeneration parity remains unqualified. This increment uses ordinary Lists and an HTML reading companion in SharePoint, with a maintained web draft guide. No desktop Word, premium runtime, AI or new permission is needed. Generated reader-facing exports are snapshots, labelled with their source item/version; reopen the live record for changes. No continuous guide synchronisation is claimed.

Recover through native version history or export the complete record/history and restore a separate reviewed copy. Keep original key/identity as provenance; do not overwrite a newer human edit. Retain source/template/guide pins. Reconcile unknown write outcomes by unique key before retry. SharePoint history is not immutable retention or an administrative security boundary.

## CLI and interpretation

Use `.venv/bin/python -m scripts.ppg_relationship_context candidates` with
`--subject-uid`, `--leads`, `--inventory`, `--inspection`, `--original` and a new
`--output` file. Ambiguous or absent targets remain unresolved; no guessed identity
is inserted. This prepares private payloads, not native writes.

The `context` command takes normalised `--relationships`, `--document-uid`,
`--document-version` and a new `--output`. It validates accepted hierarchy cycles,
then traverses exact endpoint versions. Accepted governing/variation/implementation
links support upstream/downstream context; supersession history is returned
separately so an obsolete document is not presented as governing authority.
References remain typed links. Proposals do not enter accepted traversal; links
from another edition are shown separately rather than applied to the current one.

In this pilot, the requested-edition graph has no accepted links. This means none
are recorded, not that the document has no dependencies. Six historical proposals
remain visible under other-edition context. Reconcile identities, operative
editions and actual passages before accepting a relationship. Consolidation needs
its own content comparison and human decision; an explicit reference or title
match alone cannot support it. Native form acceptance enforcement remains open.

A later retained-text comparison adds two Proposed links: audit governance and a
discharge-flow cross-reference. They are review suggestions supported by passages
from both documents, not existing explicit-reference assertions. Target versions
bind retained original bytes; current applicability remains unverified. Two
exact native readbacks/replays create zero duplicates. The complete eight-record
export is carried into successor review pack4; historical proposals do not become
accepted upstream authority or automatically apply to the requested current
edition. See [comparison and recovery](retained-text-pair-review.md).

## Recovery

Retain the original/inspection source archive, passage inventory, candidate ledger,
exact seed payload, native keys/IDs, full exports and storage receipts privately.
Query a key before retrying uncertain creation. Different stored content or a
changed human state stops seed replay without overwriting it. Export available
history before corrections and recover into a separate qualified target. No
upstream edit, clinical decision, notification or permission change is introduced.

## Local helper and integration contract

[binary_publication.py](../tools/policy-editions/binary_publication.py) performs
no network operations. It prepares a body-free, same-site, isolated fictional
copy fragment with explicit retry disabled; verifies actual independently
downloaded binary bytes; and prepares a non-deployable publication-event intent.
It is deliberately not a complete native flow or a replacement for the purpose
owner's reviewed runtime authorisation resolver.

The byte verifier requires separate physical source/issued identities, exact
opaque tokens, native versions and lengths before and after download. It compares
the actual bytes and calculated SHA-256 against the reviewed prepared scope.
Strings, supplied hash assertions alone, changed source/target metadata, byte
mismatch and source/output overlap are refused. Issued pins remain separate from
the prepared scope and original-source provenance.

The native file mapping is explicit: retain `UniqueId` and opaque `ETag` exactly;
map `UIVersionLabel` to `nativeVersion`; convert a strictly positive decimal-string
`Length` to its integer byte count; combine the verified HTTPS origin and native
`ServerRelativeUrl` for `DocumentReference`. Wildcard tokens, invalid lengths and
noncanonical paths refuse. Mapping the retained actual final prepared-file metadata
reproduced its qualified receipt pins exactly; no native operation was performed.

The event intent requires one actual retained final authorisation and all four
explicit same-scope purposes in complete nonconflicting history, including native
row identities and tokens, predecessor links and one readiness identity. Missing,
ambiguous, adverse, open, competing or superseding histories hold. Actual runtime
profile, chronology, complete consultation/readiness, source/baseline/template/
receipt/case checks and final frame brackets must still come from the purpose
owner's reviewed same-execution graph. A local helper result is not permission to
skip those checks or publish from a caller-provided success flag.
In particular, the purpose producer binds its decision reference to route reference,
version, full profile hash and purpose code. The local helper's nonempty-reference
check does not validate that relationship or chronology. The runtime owner must
retain those stronger checks; a helper pass is not full-purpose qualification.

The publication intent preserves the reviewed prepared scope and uses a separate
issued URL and UID/token version reference. An identical retained payload proposes
zero creates and preserves its original occurrence date. Changed payload under
the same event identity refuses; native storage must also enforce uniqueness.
Publication input fields use an explicit allowlist. Correction/supersession links,
native row IDs, GUIDs, row tokens and caller-supplied parent/scope overrides are
refused rather than merged. No corrective-publication workflow is qualified.
No real policy edition, effective date, review date, circulation or controlled
publication status is inferred.

## Required native sequence before acceptance

1. Resolve and revalidate the current prepared revision, complete readiness and
   purpose histories, exact retained final authorisation, route profile and all
   context pins in the reviewed owner graph. Current Deferred/Open evidence holds.
2. Read the complete exact-name destination collection. An existing output is a
   reconciliation case, not permission to overwrite or replace a human edit.
3. Pin source metadata, perform the absent-only server copy with retry disabled,
   then read source and issued metadata again. A failed or timed-out copy has
   unknown effect until reconciled; preserve any output and original run evidence.
4. Independently download source and output, verify length, exact byte equality,
   calculated SHA-256 and unchanged metadata. Copy success alone is insufficient.
5. Before the sole possible publication event append, refresh the complete owner
   frame, authorisation row token and histories, and the measured issued/source
   pins. Append only after all actual binary proof and current-context checks.
6. Read back the exact event and recheck the frame. Identical replay creates zero;
   changed payload, edited output or uncertain effect holds. Retain history and
   reconcile rather than automatically retrying a copy or event append.

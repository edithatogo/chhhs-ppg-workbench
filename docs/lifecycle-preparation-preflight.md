# Selected-case preparation prerequisite

> Current workflow baseline: [versioned register and status reconciliation](workflow-documentation.md). Dated qualification sections below retain their original scope; read the current baseline before treating an earlier limitation as current.

The native Lists-selected preflight checks the current supported fictional case,
its saved request and original source through the reviewed context graph. It then
reads the retained ownership-projection commit by its privately pinned file
identity and version, brackets that read, and requires matching case, current case
ETag, accepted fictional role/status, source scope and baseline identity/version.

The initial qualification held because no qualified prepared-revision binding
existed for this occurrence. The later [coexisting reader](lifecycle-case-work-composition.md)
now qualifies an actual selected, edited draft; this document retains the earlier
missing-prerequisite slice. The result separates `originalSourceScope` from
`preparedRevision=null`, reports preparation unqualified and consultation unopened,
and directs the document owner to supply the separate case/source-bound output.
Neither the original source nor an incomplete draft belonging to another case can
stand in for that output.

The [builder](../tools/lifecycle/build_preparation_preflight.py) consumes private
approved context, connection and commit bindings. It emits only GET operations and
has no positive progression branch. Supplying a prepared-revision binding to this
missing-prerequisite profile is refused: the actual output and its consumer must
first be qualified. This is a useful native hold, not completed document generation
or consultation implementation.

## Contract for the next consultation slice

The next consumer needs the actual prepared file's identity, native version,
opaque ETag and byte hash, plus the case/occurrence, original source and template
versions, generation job and output revision. Keep the original source scope and
prepared-artifact scope separate. Verify actual content, edit/save/readback,
variable sections and retry preservation through the existing document route.

Consultation must bind each requested response to the exact prepared-artifact
scope and explicit required-role coverage. Missing, stale, declined, conditional,
conflicting or unverified responses must leave coverage unresolved; timestamps
cannot select a current decision. No coverage pass or consultation opening is
claimed until that connected native consumer and evidence exist. No sends, new
roles, assignments, access changes or policy approval are implied.

# Full review Word generation

The existing manual M365 package flow now produces a full maintained review Word
document, an evidence ZIP and an optional PDF. Its original fixed-cover request
remains the default and keeps its original script and job fingerprint.

Open the existing package flow, enter the full request ID from the private operator
handoff and select Run. The saved DOCX, pack and separate PDF result are in the
same SharePoint evidence location. Leaving the request input blank keeps the
fixed-cover default. Change the existing output-revision property for a new
revision; no second JSON revision edit or local document generation is required.
Changed case/source selections still need an explicitly consistent frozen input.
The [native case-intake increment](native-case-package-intake.md) now prepares
supported source-only selections inside M365 and preserves the historical baseline
when the catalogue has advanced.

## What is qualified

The maintained 34-control template has scalar/multiline content, comparison and
consultation paragraph groups, optional text and explicit evidence hyperlinks.
The historical fictional example has two comparison and three consultation rows
and an inspected seven-page PDF. A separate current proposed fictional occurrence
has no recorded review events and produces a two-page source-only full DRAFT.
Its findings and ownership acceptance remain unresolved. Native zero groups,
blank optional text, long text and Unicode were also checked.

Actual saved DOCX/ZIP/PDF, all supplied fields, record identities, working link
targets and unchanged original evidence bytes were independently read back.
Word for the web editing, save, close and viewing reopen preserve one scoped
technical edit and all other content. Native retry preserves an edited output by
refusing before every writer. Recovery after DOCX/ZIP creation but before the
completion receipt reuses the exact file identities, versions and bytes and
finishes the missing receipt and PDF. The normal manual flow is restored.

## Existing M365 route

The preferred SharePoint structured-generation prerequisites were checked on
20 October 2026. [Microsoft requires an assigned Copilot licence for form/template
creators](https://learn.microsoft.com/en-us/sharepoint/copilot-in-sharepoint-structured-document-generation);
the current account's assigned SKU read does not show that entitlement. This is
an account-scoped result, not a tenant-wide absence claim. No purchase, assignment,
consent, billing, permission or shared-library schema change was made.

The fallback reuses the existing Standard Excel Office Script runtime. Template
compilation is one-time maintained authoring. For each request, Power Automate
reads pinned template parts, structured inputs and the frozen source pack from
SharePoint; the existing native script creates the new Word document and ZIP.
Standard OneDrive PDF conversion follows the verified core completion. A PDF
failure is reported separately and leaves the usable DOCX and pack intact.
The saved action inventory contains only the existing SharePoint, Excel and
OneDrive connector families; it contains no premium Word or AI-credit action.

## Preservation and limits

A separate read-only lifecycle adapter matches the selected case, occurrence,
source identity/version/hash and, where present, the exact candidate revision.
Other-revision findings stay historical. New proposed occurrences inherit none.
The catalogue-backed current selector retains its original mismatch guard. The
separate native recorded-baseline mode now admits the dated selection against its
retained proof, with the observed draft pinned separately. Case history is preserved.

Each immutable revision records source/template versions, included records,
request/input/engine pins and actual saved output identity in existing native
claims and receipts. Same-job retry verifies and reuses completed output. Changed
inputs or an edited output require a new revision. Source records remain read-only;
generation does not record review, approval, publication or acceptance.

The supported shape is this full maintained review document. Original evidence
files remain unchanged within the included frozen pack; arbitrary attachment
merging is not implemented. Empty repeat arrays omit their groups; optional blank
text has no placeholder. Section headings can remain. Arbitrary conditional
section rules require separate qualification. The bounded kernel limits are
2MB total raw input and 4MB wire data, not a proved platform maximum; 50 rows per
group pass local checks, while native evidence demonstrates zero and 2/3 rows.

Word-web use is qualified; desktop edit/reopen is not. No Windows-only authoring
step was required for this fallback. Native case-to-input generation now covers the
declared [source-only intake contracts](native-case-package-intake.md). Positive
catalogue-current native acceptance and additional document shapes remain separate.
Private native targets, request IDs, detailed receipts and output links remain in
the private operator handoff. The broader track stays open for remaining scope.

## Findings

### Medium — Capture limit is enforced after an unbounded read
- **File**: `scripts/ppg_source_surveillance.py` (Lines L56-L58; stored capture loading L91).
- **Context**: Path.read_bytes reads the entire supplied file before the10MiB check. An11MiB fictional input allocated over11MiB before rejection; larger files can exhaust memory, and a device/FIFO input is not rejected as a nonregular file before reading. The advertised capture limit therefore does not bound acquisition into memory. Stored capture loading is likewise unbounded.
- **Suggestion**: Require a regular file, check size, and use a bounded read of limit+1 bytes (then reject oversized data); apply equivalent bounds to stored raw capture loading. Test oversize/nonregular rejection and source preservation. Keep validation before destination creation.

### Medium — Standalone comparison report omits source/version provenance
- **File**: `scripts/ppg_source_surveillance.py` (Lines L117-L132).
- **Context**: A reproduced edition-1 to edition-2 comparison with identical bytes produces version-reference-changed but emits neither native version reference. The report also omits familyId, canonical URLs and snapshot receipt references/hashes. Once copied from its invocation context, it cannot identify which family/source or versions were compared; sourceKey can be reused across families. Raw snapshot receipts preserve this information, but the report does not bind or point to them.
- **Suggestion**: Include family identity, canonical source URLs and before/after native version references, plus deterministic snapshot receipt hashes or explicit immutable references. Add a version-only change regression asserting the reported versions and source bindings. Do not include denied-content metadata when expanding provenance.

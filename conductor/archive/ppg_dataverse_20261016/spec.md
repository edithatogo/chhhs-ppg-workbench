# Dataverse migration

Implement the selected migration increment with source fidelity and recovery.
First identify the Lists limitation, exact existing environment, solution/publisher,
licensing/capacity/security and intended scope. Do not provision or select another
project's environment from its active credentials or browser tab. Keep SharePoint
operating until native parity and an explicitly scoped cutover are qualified.

Prepare current declared-schema mapping and offline normalized-export reconciliation
without inventing physical prefixes or changing tenants. Preserve DocumentUID,
CaseUID, separate event identities, all25 source fields, raw dates/month precision,
local decisions, blank/unknown states and explicit relationships. Retain evidence
files/native history and original URLs/access; do not silently relocate them.

Duplicates, orphan links, identity exceptions, missing/extra rows and field drift
hold reconciliation. Supplied JSON parity does not establish export completeness,
security, owner/history/file/flow parity or native acceptance. Native migration
needs actual target schema/readback, staged fictional import, repeat/recovery,
full export reconciliation and validated rollback before any cutover decision.
No licence/access changes, production migration, deletion, assignment, messages or
source retirement follows from offline preparation.

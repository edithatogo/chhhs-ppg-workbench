## Findings

### [High — fixed] Verify the actual Git push URL

- **File**: `scripts/publish_github.py`, lines24–27,61–62,85.
- **Context**: A matching fetch URL can coexist with a different or additional
  push URL. A publisher must not rely on the local hook being installed to reject
  a destination outside the reviewed private repository.
- **Suggestion applied**:

```diff
+ urls = git remote get-url --push --all origin
+ require exactly one matching reviewed destination before push
```

The regression rejects mismatched/multiple destinations and preserves the explicit
reviewed-commit push without force. The pre-push hook independently checks its actual
remote URL, review receipt and private destination.

### [Medium — fixed] Bound object sizes before materialisation

- **File**: `scripts/check_publication.py`, lines84–110.
- **Context**: Checking size after collecting every blob would allow unnecessary
  memory allocation before refusing an oversized tracked artefact.
- **Suggestion applied**:

```diff
+ query object metadata with git cat-file --batch-check
+ validate identity/type/per-file/aggregate size before reading blob contents
```

An oversized-input regression verifies refusal. A real shared-index commit exposed
a stalled large metadata-pipe request; metadata reads now use at most 32 objects
with 30-second bounds and individual blob reads have no input pipe. A multi-chunk
regression and the 485-file staged scan pass. Only the verified failed read-only
child was terminated; Git released its own lock and retained the other staged work. Existing identity, UTF-8/binary,
symlink, unsafe-path and snapshot-completeness checks remain in place.

# Guided workspace and case navigation

Selected by the user on 17 October 2026 as an existing-permissions usability increment.

## Outcome

Make the existing four Teams surfaces usable through five explicit tasks: find a
policy, open a case, prepare a package, record a review and resolve an exception.
Extend the existing Start Here managed controls, forms and views. Reuse delivered
identity, readiness, assurance and consultation paths; no new workflow engine.

## Deliverables

- A task map with the actual canonical destination, input, supported action,
  expected result and manual/operator designation for each task. A downloaded
  script is never labelled an executable Teams button.
- Case forms grouped into source context, proposed work, review and implementation;
  use supported conditional visibility only when the exact operation is available.
  Keep unknown/pending states and access to all editable human fields. Hiding a
  field is not security or validation. Do not change column types or requiredness.
- Refine existing next-action/exception views: missing evidence/action, recorded
  ownership awaiting acceptance, overdue confirmed dates and identity holds.
  Preserve free-text target dates; pending/non-date values are not overdue. No
  guessed responsible person, automatic assignment or clinical judgement.
- One consistent case landing route using existing item links/fields to source,
  draft, comparison, readiness and package. Resolve by stable case/document identity;
  never use title alone or attach another case's generation receipt. Distinguish
  latest draft, verified package and historical output. Missing links stay explicit.

## Acceptance

All five task routes open the intended existing resource in the supported Teams
web/SharePoint route. Read back forms/views and demonstrate representative pending,
held, missing-link and confirmed-date examples without editing real decisions.
Check keyboard navigation, meaningful labels and text alternatives to colour.
Repeat deployment adopts existing objects and preserves unrelated controls, source
values and original case. Retained example may be inspected read-only; any native
write examples must be clearly fictional and isolated, with a cleanup receipt.
Existing Teams desktop acceptance remains closed; no desktop capture requirement.

## Fallbacks and exclusions

If form configuration is unavailable, retain native form and provide grouped field
instructions. If a public view cannot be managed, reuse an existing suitable view
or permitted personal view, clearly labelled as personal. If page editing is denied,
prepare a library guide through an already permitted route. Never alter access to
make a link work. No custom app, new List, extra tab or new document generator.

## Existing-permissions execution contract

Use [the shared permission and delivery contract](../../../docs/usability-delivery-plan.md).
Before a native change, read the exact existing target with the intended account,
record the available operation and preimage privately, and confirm its writer.
Recorded historical access is a starting point, not current operation proof.
Use only existing site/List/library rights and qualified clients. No tenant admin,
new consent/app registration, licence purchase/assignment, access changes, premium
runtime, new site, schedule or notification is required or authorised.
An unavailable operation takes its documented fallback; record the limitation and
continue independent tasks. Never call a fallback the unavailable native feature.
Preserve source fields, case decisions, original files, version history, unrelated
controls/views and inherited permissions. Native save/readback and repeat safety
are separate from local checks. No new deployment is claimed by this plan.

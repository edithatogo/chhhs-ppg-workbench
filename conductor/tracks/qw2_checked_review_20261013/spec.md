## Technical deliverables and completion

1. A reusable package template captures case/baseline/version, source/control
   evidence, editable draft/change links, existing route, actual responses and
   next action. Generated status is DRAFT; no acceptance is inferred.
2. An offline generation workflow demonstrates populated editable output,
   input/source preservation, protection of existing edits and explicit pending
   business fields. No new case, notification or native write is introduced.
3. The preserved IETP example demonstrates editable instruments, source fidelity,
   native package navigation and distinct direction/review/approval states using
   retained file/case readback evidence. Recorded native evidence is labelled;
   local generation alone is not a deployment claim.
4. A technical handoff records what is usable, how to repeat it and limitations.
   Registry/handoff and native rendering/case writes stay with QW1.

## Inputs, boundaries and deferred work

Use the dated baseline and retained sources as examples; live sync, AI, a new
application and actual responsible reviewer participation are not dependencies.

endorsements as business completion. Source facts remain separate from proposals.

Actual policy assessment, consultation, reviewer/role acceptance, capacity,
agreed dates, operative-policy judgement, authorisation and implementation are
later operational use. Do not pursue them to close this software milestone.
The local native renderer has example-specific wiring; unattended arbitrary-case
rendering/publication is not claimed. No new family, people or source/native writes.
